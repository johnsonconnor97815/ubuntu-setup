# Sol 负责完成与验证，Astra 按需提供建议

主会话由 `gpt-6.1-sol` 负责规划、工具操作、修改、验证和交付。任务完成情况由实际证据
核对。Astra 按需回答明确的设计问题、矛盾证据或合理排查后仍存在的疑点；任务复杂或即将
交付不自动触发第二轮模型评审。没有固定咨询次数，简单任务通常直接处理。

| 角色 | 模型 / 推理强度 | 职责 |
| --- | --- | --- |
| 主会话 | `gpt-6.1-sol` / `xhigh` | 完整执行与最终验收 |
| `routing_astra_advisor` | `gpt-6-astra` / `xhigh` | 根据完整可用会话提供意见，不使用工具或执行 |
| `routing_sol` | `gpt-6.1-sol` / `xhigh` | 按需要处理独立的较大工作，叶子代理 |
| `routing_luna` | `gpt-6-luna` / `low` | 按需要提取明确范围的数据，叶子代理 |

## 任务怎样完成和验收

- 多步骤执行任务先明确用户要求的结果、相应检查和剩余工作。优先复用项目已有记录；
  长任务需要时保留可继续使用的记录，小任务不额外生成计划文件。
- 沿用有效授权，将实现推进到相关验证。计划写好、代理启动、源码修改或编译成功，
  都不能单独代替用户要求的实际结果。存在阻塞时保留已完成部分，继续不受影响的工作。
- 根据改动选择已有测试、编译、配置校验、接口或实际运行检查，说明每项检查能证明
  什么。模型或另一代理认为正确不算验证证据；未运行的行为仍标为未验证。
- 根据失败输出和新证据修正，修正后只重跑失败或受影响的检查。没有相关变化或新的
  排查假设时，不反复重试，也不追加笼统的模型评审。
- 交付前逐项对照需求、实际证据和剩余工作，区分完成、部分完成、失败、阻塞和未验证。
  规则加载成功只能证明配置已加载，实际完成率、返工和耗时改善仍需用真实任务验证。

这些要求与按需协作规则统一维护在 [AGENTS.md](AGENTS.md)，部署时合并其中的受控区段。
不需要为了这组行为要求改动模型、服务档位、MCP 或权限设置。依据是 OpenAI 的
[任务完成与验证最佳实践](https://developers.openai.com/codex/learn/best-practices)及
[子代理适用范围与开销说明](https://developers.openai.com/codex/subagents)；规则不是执行器
强制的验收程序，也不保证模型每次都遵守。

## 顾问怎样获取上下文

使用命名角色 `agent_type="routing_astra_advisor"` 和 `fork_turns="all"`，**不传显式 model
或 reasoning_effort 参数**。V2 命名角色路径应用角色文件的模型与强度；这与直接覆盖完整
分支的模型参数不同。若当前客户端拒绝这组调用，停止并说明不支持，不绕过限制或偷偷
改成简短说明模式。短问题可以帮助聚焦，但不能用选取的摘要替代完整会话。

每次新咨询应继承当时的完整可用历史。旧顾问若没有完整收到之后的变化，不能当作已看到
最新会话。平台已有的压缩和记录范围仍适用：完整分支不恢复被丢弃的内容，也不是零上下文
成本。顾问只根据继承会话推理；缺少事实时让 Sol 补充，不自行读文件、运行工具或执行修改。

顾问通常用不超过 500 tokens 返回状态、意见、会话中可见依据及未确认范围。Sol 核对意见，
决定接受或拒绝；修正后只重查失败或受影响项目。意见不是用户授权，也不是成功证明。
公共规则维护在 [AGENTS.md](AGENTS.md)。

## 与原生 Claude Code advisor 的区别

Claude Code 的 [advisor](https://code.claude.com/docs/en/advisor) 是服务端顾问工具，能看到
完整会话。本目录是使用 Codex [自定义子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents)
的本地近似方案，不是同一个服务端功能。截至 2026-10-10 的文档查证没有找到 Codex 对等的
原生 advisor 配置键。不要把自定义角色描述成原生顾问服务。

Astra 的“不调用工具、不执行、不创建子代理”是行为指令，不是程序强制的权限隔离。
本机 `codex-cli 0.162.1` 的角色独立 sandbox/MCP/agents 覆盖没有被验证为有效限制。
即使一次运行没有调用工具，也不能保证未来每次都遵守。V2 深度配置同样不是已验证的硬边界。

## 文件与生效范围

- `config.toml` 是合并片段，不能替换整个用户配置。主模型和可选 Sol 执行代理默认使用
  `xhigh`，Astra 顾问同样使用 `xhigh`；用户之后的明确选择优先。
- 角色文件放到 `~/.codex/agents/`；受控规则区段合并进 `~/.codex/AGENTS.md`，保留其他规则。
- 新会话加载新角色，已运行会话不保证即时重载。项目配置、命令行参数和后续指令可以覆盖
  全局选择，实际行为要核对当前会话。

2026-10-10 按用户要求将默认组合设为 Sol `xhigh` + Astra `xhigh`，可选 Sol 执行代理
同步使用 `xhigh`。全局主模型原本已是 `gpt-6.1-sol` / `xhigh`；登录、供应商、MCP、插件、
权限及 Luna 角色保持原样。旧 `routing_sol` 同步为可选独立叶子工作代理，Luna 保留但不自动
委派。备份、权限、哈希、候选差异和恢复资料在 `~/.local/state/codex-routing/<UTC>-advisor/`，
不进入仓库。恢复前核对当前哈希；存在后续改动时拒绝覆盖。

这次测试只证明该版本该次调用，不证明所有任务都遵守协议，也不是费用或速度基准。

完整会话咨询仍增加调用、上下文和等待，不能保证节省。此前 A/B/C 小型合成实验测试的是
