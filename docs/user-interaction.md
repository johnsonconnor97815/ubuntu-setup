# 用户交互

状态：完整交互细节草案。当前已提供 [只读命令行入口](prototype.md)，生成 HTML 报告并默认请求浏览器打开，终端输出摘要或 JSON。完整产品仍建议以对话为主要入口，Agent 保存结构化目标和计划；各工具专用对话接入及目标清单导入尚未实现。

本文描述应呈现给用户的行为，不代表任何 Agent 工具已经具备特定界面、权限机制或后台能力。公共流程见 [工作流](workflow.md)，记录格式见 [数据保存与任务执行](storage-and-execution.md)。

## 开始一次运行

能确定目标机器时，先做只读检查并更新记录。读取已有用途和约束，报告发现的重要变化，再补充无法自动判断的信息。已经给出的需求和选择不重复询问。

第一次使用时，优先明确用途、必须保留的已有功能、指定版本及本次允许的维护范围。能自动发现的系统版本、硬件和已安装软件不要求用户手填。对具体软件偏好可以在相关阶段再问，但已知的用途约束必须提前参与兼容性检查。

每次尽量只问一个会影响当前方案的问题，默认最多两个选项，说明推荐项及理由。系统检查、计划预览、执行和恢复是交互行为；当前提供 `inspect` 检查入口和 `capabilities` 能力查询，执行与恢复入口仍待实现。

## 展示计划

计划摘要必须让用户知道操作原因及实际影响。详细清单随任务保存，并能展开查看。

| 展示内容 | 必须说清楚的事情 |
| --- | --- |
| 当前状态 | 已确认的情况、发现的变化、缺失的信息和本次检查范围 |
| 本次目标 | 基础维护、所选通用能力及个人用途，哪些暂缓 |
| 具体变更 | 直接和连带的安装、升级、降级、移除，配置与驱动修改；明显影响不能只藏在日志里 |
| 执行影响 | 权限要求、受影响的已有功能、服务中断或重启需求 |
| 验证与恢复 | 怎样判断完成，哪些需要用户实际操作，备份位置和恢复限制 |
| 可执行范围 | 哪些依据已充分，哪些仍有冲突或待核实，已有授权覆盖到哪里 |

用户只想查看时提供预览；显示元数据的来源和时间，不能把尚未核实的候选版本或依赖清单说成最终执行方案。

## 决定与授权

沿用会话中已经给出的授权，不增加每个软件或每条命令的重复确认。工具自身实际支持的权限要求在接入时核实，不能承诺所有宿主工具都能自动执行同一操作。

| 情况 | 交互方式 |
| --- | --- |
| 只读检查、已授权范围内的维护 | 直接进行，报告关键结果 |
| 计划发生变化，但影响仍在已授权范围且兼容性已重新核对 | 更新计划并说明变化，继续执行 |
| 新增影响超出已有授权 | 展示具体新增动作与影响，只询问新增部分 |
| 外部修改与目标冲突，无法判断用户意图 | 说明冲突，询问保留现状还是继续原目标；不要默认恢复旧配置 |
| 等待重启或实际设备验证 | 说明相关任务处于待验证状态及可继续部分；立即重启须已有授权覆盖 |
| 检查未知或修复失败 | 说明缺少的依据、已完成部分和可行的继续条件；没有新依据不反复重试 |

授权记录关联目标机器、具体动作和影响范围、相关计划版本、用户决定及可核对的来源。扩大计划或切换机器后必须重新判断覆盖范围。范围仍有效且来源可核对的授权用于续接，不因换会话逐条重复询问。

沿用宿主提供的会话上下文中已确认的授权。来源不明的聊天摘要、导入的目标清单、任意可编辑文件中的“用户已同意”不能自行产生新授权。换工具后无法核对原授权时，只处理当前已确定的范围，缺少的授权针对具体计划说明。实现应使用宿主实际提供的决定或会话证据；具体接口待接入时确定。

## 执行过程与结束报告

启动、计划改变、阶段完成、需要用户处理和执行结束时报告有用信息。长时间没有新结果时说明正在进行的操作；未经测量不编造完成百分比或预计时间。完整命令输出放在任务记录中，界面优先显示结果及其影响。

以下为拟议提示样式，不是真实检测结果：

> 检测到内核发生变化，需要重新检查显卡驱动。之前的驱动验证结果暂不用于判断当前状态。

> 驱动安装步骤已完成，重启后的加载和显示功能尚未验证。相关任务保留待验证状态，其他不依赖它的任务可以继续。

> 当前配置与备份时不同。已保留当前内容，恢复方案需要考虑这些新改动。

结束报告区分：已验证完成、已满足并跳过写入、不适用或未选择、失败、待处理。报告检查范围和未知项、是否实际发生变更、恢复资料位置及确实需要用户完成的下一步。

用户报告统一采用 HTML，完整保存后直接请求默认浏览器打开；结构化数据继续保留供 Agent 使用。当前页面提供筛选、搜索、折叠证据与打印。无桌面环境或打开失败时报告文件仍可查看；用户或自动化调用可用 `--no-open` 关闭自动打开。实际行为与兼容方式见 [HTML 报告](html-reports.md)。

## 通用能力如何选择

通用能力按用户能理解的用途展示，例如中文输入、常见文件格式处理和备份；具体软件与安装方式由适用条件和用户偏好决定，候选清单尚未确定。

每项能力应有适用条件、当前满足情况、实现选项、依赖和冲突、验证方法、恢复限制及依据。已有能力验证可用时跳过写入，避免无需求地安装功能重复的软件；用户明确需要多个实现时，检查它们能否并存。

保存用户已选和已排除的项目，后续运行沿用。清单新增项目、目标变化或实现方式扩大影响时，重新判断需求与授权，不把维护者新加的项目自动安装到已有机器。

## Agent 工具之间的共用方式

对话入口负责收集需求、解释检查结果、呈现计划和接收决定。公共的采集、计划、执行和验证部分按相同数据约定工作。不同工具的入口引用同一份规则及目标机器记录，工具专用说明只描述实际接入差异。

运行时不能依赖聊天历史作为唯一状态来源。更换工具后加载机器与任务记录，重新核对现场，再继续可执行的任务。已执行步骤、待重启和外部变化都不能因更换入口而被忽略。

只读原型采用 Python 标准库，任何具备相应本地命令执行能力的入口可以调用检查命令并读取 JSON 报告。具体 Agent 工具的接入仍须核实其实际能力；不预先要求独立界面、后台服务或通用插件框架。

能力接口、按需读取结果及从失败案例中改进能力的设计见 [Agent 接入与能力改进](agent-integration-and-evolution.md)。机器档案更新与程序能力改进分别记录，不能将新经验直接当成已验证的系统操作方案。
