# HTML 报告与自动打开

状态：`0.8.0` 已实现。所有新生成的用户检查报告使用 HTML，保存完成后默认请求系统的默认浏览器打开。报告所用 JSON 记录继续保留，供 Agent 读取和后续续接。

## 使用

```sh
./ubuntu-setup inspect
```

命令先只读采集和检查，再把报告保存为私有状态目录中的 `runs/<run-id>/report.html`。快照、检查结果和报告全部保存，当前索引发布完成并释放写入锁之后，才请求桌面打开报告。终端显示结果摘要、文件路径和打开请求的状态。

模拟检查也使用同一种 HTML 报告，并在页面明确标为模拟数据。自动化调用或无需弹出页面时，可以关闭自动打开：

```sh
./ubuntu-setup inspect --no-open
./ubuntu-setup inspect --format json --no-open
```

`--format` 只决定终端输出摘要还是 JSON，不改变报告文件的 HTML 格式。`--format json` 本身不关闭自动打开，调用方需要时显式使用 `--no-open`。`capabilities` 是能力查询，不生成检查报告或启动浏览器。

## 固定报告模板

模板实现在 `ubuntu_setup/report_template.html`，内容由 `report_text.py` 和 `report.py` 填充。标题固定为“系统检查报告”，开头先说具体发现，并把用户要做的事放在检查清单之前。每次运行沿用下面的顺序。

| 顺序 | 默认显示的内容 | 写法要求 |
| --- | --- | --- |
| 报告抬头 | 标题、来源、操作系统、检查对象、检查时间 | 区分本机系统、虚拟机等环境；模拟数据始终明确标记 |
| 检查结论 | 最先需要关注的具体发现及尚未确认的影响 | 不以数量代替结论；有其他问题时提示下方仍有记录，不合并故障原因 |
| 接下来怎么做 | “你现在要做”和系统助手的后续建议 | 用户待办排在前面；设备确认只列尚未确认的项目；建议不代表已执行 |
| 1. 需要处理的事项 | 已发现的问题、后续检查和维护、未查清事项 | 三者分开；所有异常和待完成项都有位置，设备待办已在上方显示，不重复列一遍 |
| 2. 完整结果与详细记录 | 按领域分类的全部结果表和逐项说明、电脑信息、前后变化、采集记录与限制的入口 | 默认收起；没有脚本时也能展开全部记录；统计、筛选和搜索放在相应详情里 |

分组数量和完整统计按检查项计数。例如，一个检查发现两个后台项目失败时，仍是 1 项检查；说明另列两个失败项，不能写成两个已查明的故障原因。没有足够结果时明确无法判断，不给健康评分。正文、完整结果表和技术记录来自同一份检查记录。

已发现的问题先于后续维护。问题内部先列系统盘、软件安装和软件冲突，再列驱动匹配、设备功能、后台任务及其他项目；这是阅读顺序，不是新的严重程度或故障原因判断。驱动匹配错误和后台报错分别保留，不能推断它们来自同一原因。没有异常时，结论反映待完成事项、程序错误或信息不足；不能只因没有失败项就写系统健康。

例如，已核对的 `nvidia-cdi-refresh.path`、`nvidia-cdi-refresh.service` 可显示为“NVIDIA 后台任务报错”，同时说明失败项数量、原因和使用影响未查明。这只是说明对象，不表示显卡故障。仅当全部对象都属于这两个名称时使用该归属；混合其他名称或名称相似时不套用。2026-09-19 通过本机相应单元文件的描述核对名称，未据此判断当前实际故障原因。

## 详细信息和交互

- 每项完整检查保留结果、影响与限制、后续建议，以及原检查名称、结论、对象名称、原因编号、规则版本和证据。读取成功与功能验证仍分别表达。
- 页面第一屏之后显示“按分类看结果”：系统和基础环境、软件和更新、驱动和设备、后台任务和设置。每个分类卡片显示总数和是否需要关注，点击后展开该分类的逐项说明。
- 全部检查结果表默认展开，并按上述分类排列；组内再按结果状态排序。逐项说明默认按分类收起，Agent 研究任务和原始记录放在后面的技术附录。分类只用于阅读，不改变检查结论或严重程度判断。
- 重点问题的“查看记录”、用户待办的设备记录链接和完整结果表的项目名称，直接打开对应检查和技术依据；如果筛选隐藏了该项，跳转时清除筛选并显示它，包括重复点击同一个链接时。
- 机器信息与原始采集记录保留完整值和覆盖范围；没有读到的信息不借用历史值填充。
- 逐项说明支持按状态筛选，并搜索折叠的技术名称。筛选只影响逐项说明，正文的重点事项和完整结果表始终保留。
- 打印使用 A4 版式，包含正文和全部检查结果表。打印时临时展开完整结果表，结束后恢复；未展开的其他详情不打印，已展开的详情按当前范围打印。打印逐项说明时忽略筛选，保留全部检查。
- 时间、检查环境和模拟数据标记始终显示；机器变化、规则变化、失效结论及历史恢复记录保留在后面的详情中。

结果、证据和限制均从同一份结构化记录生成。报告不另做兼容性判断，也不推断故障原因。重要的未知事项、影响和限制直接显示，技术详情折叠不能替代这些说明。读取时间显示为本机时间，原始时间保留在 HTML 的 `time` 标记和记录中。

## 文案与检测分开维护

`ubuntu_setup/report_text.py` 维护已核对的中文说明，按 `check_id`、`reason_code` 和结果选择文案；不通过匹配中文原因句来推断结果。检查程序错误和未实现状态优先独立展示。各项数量取自检查记录中的对象清单，不能替换为已查明的故障原因数。

`reason_code` 是 `0.4.0` 新增的可选原因编号，原有 `result`、`reason`、`next_step`、证据、规则版本与判断含义保留。缺少编号的旧记录或未识别的新编号使用保守说明，原始内容仍可展开读取；不会把其他分支的文案套过来。存储读取时检查编号类型，旧记录允许缺省。

文案版本当前为 `9`，写入 HTML 的 `report-content-version` 和“记录文件与检查限制”区域，并通过调用结果的 `report_content_version` 返回。`0.8.0` 调整阅读顺序，把专业名称和具体版本放在详情中；例如用“系统设置需要重新读取”说明重载提示。保留 `0.7.0` 的模拟变更清单、驱动版本对照、设备确认表和全部原始证据。版本 `6` 在 Agent 后续建议中显示更新冲突复核和稳定性调查任务；版本 `7` 移除 DKMS 检查项；版本 `8` 将结果按领域分类；版本 `9` 把分类速览提前、总表默认展开、逐项说明按分类收起，并把 Agent 研究任务移入技术附录。文案版本独立于采集版本与规则版本，历史报告不改写。

后续新增或修改文案时，先保留对应的合成案例，验证数字、对象、状态、限制和处理责任，再更新文案版本。至少覆盖信息缺失、功能未实现、程序出错、真实异常、重启提示消失但尚未确认重启、驱动记录不匹配等分支。目前使用固定文案，尚未接入模型自动改写或自动采用新文案；真实用户阅读验证也尚未完成。

写作依据（2026-09-18 查阅）：[GOV.UK 清楚表达](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/)、[W3C 常见词与术语解释](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o3p01-clear-words/)、[Microsoft 错误说明](https://learn.microsoft.com/en-us/windows/win32/debug/error-message-guidelines)和 [GOV.UK 按需展开详情](https://design-system.service.gov.uk/components/details/)。通过 Exa、Tavily 和 Context7 查证；这些指南支持表达方式，不构成本机状态或中文文案效果的验证。

## 自动打开与失败处理

使用当前普通用户的桌面会话，通过系统 `xdg-open` 打开报告的本地文件地址；不安装浏览器或修改默认应用。命令参数独立传递，不拼接 Shell 命令，路径中的空格和特殊字符按文件地址编码。

| 情况 | 行为 |
| --- | --- |
| 桌面环境和打开工具可用 | 报告保存后请求打开；打开工具返回成功时记录 `requested` |
| 使用 `--no-open` | 保存报告，记录 `disabled` |
| 没有桌面会话或缺少 `xdg-open` | 保存报告，记录 `unavailable` 并提供文件路径 |
| 打开工具报错 | 保存报告，记录 `failed`，可以手动打开 |
| 请求超过 5 秒未返回 | 记录 `timeout`，不重复启动；浏览器可能已收到请求，不能确认页面已显示 |
| 报告保存或发布失败 | 不启动浏览器，返回原有检查失败状态 |

`requested` 仅说明打开工具接受了请求，不能证明用户已经看到或阅读页面。浏览器打开失败不撤销已完成的报告，也不把系统检查改为失败。

JSON 输出新增 `report_format: "html"` 及 `browser_open`，其中有 `status` 和 `reason`。`report_path` 指向 HTML 文件。打开结果仅随本次调用返回，不写回已保存的检查结论；退出码 `0` 仍表示报告完整保存。

## 记录兼容与隐私

运行状态记录新增 `report_file: "report.html"`。读取旧记录时，缺少该字段按原先的 `report.md` 核对，因此可续接 `0.1.0` / `0.2.0` 档案；不会改写历史 Markdown 报告。明确声明 HTML 的新记录如果缺失报告，不用无关 Markdown 文件替代。

旧版本程序仍只认识 Markdown 报告，不能直接用它续接已经含新 HTML 运行的目录。若要退回旧程序，应先保留完整状态目录并核实兼容方式，不能删除新记录来伪装成旧状态。

HTML 与机器快照一样保存在私有目录中，不提交仓库，也不外传。渲染时将采集文本作为普通文字转义，页面仅允许执行自带脚本，避免软件名、服务名或错误内容被当作网页代码。报告包含机器清单，分享前须按项目的数据导出规则处理。

2026-09-18 查阅本机 `xdg-open(1)`：适用于桌面会话、支持本地文件地址，返回码 `0` 表示请求成功。运行与页面验证记录见 [只读原型](prototype.md)。
