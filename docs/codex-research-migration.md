# 已有查证配置的迁移与恢复

仅在 `swkit codex-research plan` 或执行报告指出已有部署需要迁移时读取本文件。

## 处理流程

1. 阅读预览中的待改文件和冲突。脚本核对两份全局 `AGENTS` 文件中的受管块，以及 `CODEX_HOME/skills/exa-context7-research/` 中的文件指纹。非当前生效文件也要检查，避免后续切换指令来源后出现失效引用。
2. 同名文件被定制、存在额外条目、软链或无法识别的引用时，保留并报告。由用户或已获授权的 Agent 核对差异后制定合并方案；不能为了通过检查覆盖定制。
3. 沿用配置授权执行 `./swkit codex-research configure`；不需要打开报告时加 `--no-open`。脚本先保存原件、候选内容和 `recovery.json`，写入并验证完整规则，确认两份指令均无失效引用后，再将可确认的部署目录迁出发现路径。
4. 自动迁出要求目标 `mv` 支持 `--no-copy`，且部署目录与恢复目录位于同一文件系统。不满足时保留目录并报告，先制定人工处理步骤；不为此升级系统工具或回退为复制后删除。没有待迁目录的新装不受此条件影响。
5. 执行 `./swkit codex-research status`，查看报告中的 `recovery_manifest`、`retired_skill_paths` 和待验证项。新开目标 Codex 核对完整规则加载，再验证工具调用与查证行为。

仅更新仓库不迁移当前主机。中断后根据当前文件和恢复记录重跑，不只依赖上一次报告。

## 恢复

恢复资料保存在目标 `CODEX_HOME/.ubuntu-setup-research-runs/` 下的本次私有目录。

- 比较当前文件与 `recovery.json` 记录的候选哈希。内容已有后来修改时，保留这些修改后制定合并方案，不能直接覆盖备份。
- 需要恢复迁移前配置时，将指令文件与其引用的部署文件一起恢复，并核对权限、内容及引用是否有效；备份路径和迁出目录以记录为准。
- 只撤销本次新增的 MCP 和规则，不移除原有同名配置。恢复后重新检查实际加载与调用，不能承诺整组自动回滚。
- 备份可能包含凭证或私有指令，只留在目标机，不提交或粘贴到聊天中。
