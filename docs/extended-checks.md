# 5 项扩展检查

版本：`0.7.0`。5 项检查均已实现，并有独立证据、规则版本和自动测试。检查的范围有限；“已实现”不表示本机已通过，也不表示完整系统维护已经完成。

## 软件依赖与更新模拟

`packages.dependencies` 使用系统 `python3-apt` 读取已安装软件的依赖关系，并在内存中模拟一次完整更新。记录新增安装、升级、降级和移除清单，保留包版本锁定、架构和 APT 版本优先级设置。

- 当前依赖断裂或版本冲突：异常。
- 候选无法组成完整依赖方案：更新方案异常，不等于当前应用已经损坏。
- 模拟要求移除或降级：等待审查清单；不会自动执行。
- 缓存不完整、解析无法满足锁定要求：未知。
- 检查通过：只说明当前依赖和该份索引下的候选方案可解析，不证明应用实际功能。

不会调用安装提交接口。APT 的真实解析器测试使用临时文件仓库，覆盖版本冲突、依赖升级、移除、锁定和版本优先级。此项不覆盖 Snap、Flatpak、手动安装应用或任意新软件的安装方案。

## 更新和来源

默认离线读取本地索引。缓存中没有更新也不能报告“已是最新”。程序还检查是否配置了跳过来源签名或有效期验证的选项。

```sh
python3 -m ubuntu_setup inspect --online --timeout 30
```

`--online` 从已配置的软件源下载索引到私有临时目录，由 APT 核实来源和索引有效期，再使用新索引重新解析候选。不会刷新 `/var/lib/apt/lists`。配置仅继承软件源、密钥、版本优先级、架构、必要的包策略和静态代理设置；不继承本机更新钩子或代理自动探测命令，不调用安装操作。实际使用自定义网络扩展的环境可能需要另行适配，失败保留未知。

来源验证失败、索引过期和来源不可用分别保留原因类别；连接失败和超时不作为系统故障。失败后可保留独立的当前依赖检查，但不会把旧缓存冒充联网成功。临时目录由父进程管理，超时或中断时终止进程组并清理。软件源原文、代理凭据和原始错误输出不写入报告；只记录源主机名、发行分支、来源编号、索引状态和失败类别。

缓存完整性以 APT 的 `indextargets` 输出为准，不能把它列出的潜在索引或可选的 `binary-all` 文件都当作必需项。更新清单中的“来自 security 分支”只是索引来源，不是完整漏洞扫描。不检查全部安全公告、发行版和第三方软件的支持期限。

## 驱动匹配

`drivers.compatibility` 读取已绑定 PCI/USB 设备的匹配标识，以 `modinfo -k 当前内核 模块名` 取得模块文件元数据。核对当前内核版本、设备匹配表、运行中与磁盘上的模块版本，记录签名存在性和固件文件情况。检测到 NVIDIA 模块时，通过 `nvidia-smi` 测试管理接口及配套库能否交互。

磁盘模块与当前内核不匹配、管理接口测试失败，记为异常。运行中与磁盘版本不同，记为等待生效；不重复安装驱动。固件声明可能包含其他硬件修订的可选文件，缺少文件只能提出未确认项，不能直接认定设备故障。设备未匹配静态支持表也保留未知，因为驱动可能支持动态登记的设备标识。

签名存在不等于该签名受信任。此项没有自动核实全部签名链、厂商支持矩阵、相关应用库或固件实际选择。`kernel.next_boot` 仍未核实，不能由已安装的最新内核推断下次启动版本。容器和 WSL 不用于判断宿主驱动。

## 设备实际使用确认

`hardware.function` 使用现有 EGL/GLES 库创建 1 像素离屏画面，填色后读回像素，记录实际绘制器和结果。它不打开窗口、不截取屏幕、不播放或录制声音、不采集键盘输入。软件绘制通过不证明 GPU 加速可用；此测试也不覆盖所有显卡、完整桌面、性能、摄像头、蓝牙或其他外设。

屏幕显示、声音和键鼠的实际体验由用户确认。Agent 必须先获得用户对具体项目的明确反馈，再记录；不能根据模块加载、命令成功或自己的推测填写通过。例如，用户确认当前报告对应的三项都可用后：

```sh
python3 -m ubuntu_setup inspect --confirm-from REPORT_RUN_ID \
  --confirm-device display=passed \
  --confirm-device audio=passed \
  --confirm-device input=passed
```

`REPORT_RUN_ID` 替换为最新报告的 `run_id`；每项可以填写 `passed`、`failed` 或 `not_applicable`。后者表示用户确认本次不需要这项设备能力，不是程序自行跳过失败。

程序重新采集后，将报告对应的环境与当前环境比较。目标、系统、启动、内核、硬件、驱动、已登记软件、监测配置和默认配置证据改变时，旧确认失效；新提交的旧环境反馈也不会绑定到新环境。缺少关键观察时，不保存为有效确认。未变化的确认保留原时间和来源，不冒充自动测试结果。比较范围采取保守策略，普通软件变化也可能要求重新确认。

## 设置是否生效

`configs` 默认检查两类设置：

| 对象 | 已实现的验证 | 边界 |
| --- | --- | --- |
| sysctl.d | 用 systemd 选择生效文件，处理顺序覆盖、点/斜杠名称、匹配模式和排除项；将数字设置与 `/proc/sys` 当前值比较 | 非数字值不保存原文，保持未知；不覆盖所有程序设置或加载模块后才出现的设置 |
| 已加载系统单元 | 读取配置加载状态、是否等待重新加载，以及配置文件摘要 | 不含全部用户服务或未加载单元；配置无误不等于服务功能通过 |

格式无法解析或单元报告配置加载错误，记为异常。文件中的数字值与当前值不同，或服务管理器提示重新加载，记为待验证，先核对是否有意保留运行时设置。管理器可能给许多单元同时返回重载标记，报告合并为一项重载要求，不推断数百个独立故障。程序不运行 `sysctl --system`、`daemon-reload` 或服务重启。

`--watch-config` 仍可监测任意额外文件的摘要，但没有相应验证器的文件保持未验证。默认检查的非数字内容仅以摘要参与变化检测，不保存原文。

## 接口与历史记录

新增观察范围为 `checks.packages`、`checks.drivers`、`checks.hardware`、`checks.updates`、`checks.configs`，采集版本 `0.2.0`；原范围仍为 `0.1.0`。对应 5 条规则升级为 `2`。记录格式仍为 `schema_version: 1`。

旧完整范围的快照仍可读取，新增范围在下一次检查中记为采集覆盖变化；不伪造旧观察和证据编号，不改写历史报告。新规则需要的新信息必须重新采集。单项缺失、子进程超时与规则失败不会被当成通过，也不会阻止独立检查。

兼容方向是新程序读取旧档案。`0.6.0` 及更早程序不能直接读取新增范围的快照；回退代码不会自动回退档案。需要回退时使用升级前的档案备份或独立状态目录，不删除新观察来伪装旧格式。

能力说明通过 `capabilities --format json` 提供输入、版本、限制、依据和失效条件。纯规则仍不执行采集、联网或修复。增加或改进检查时，要同时更新观察校验、独立规则、文案、复现数据和适用版本，不只修改 `implementation_status`。

- [Python APT 的 Cache 和 DepCache](https://apt-team.pages.debian.net/python-apt/library/apt_pkg.html)：只读缓存、候选和依赖解析；不调用提交接口。
- [Ubuntu Noble apt-get](https://manpages.ubuntu.com/manpages/noble/en/man8/apt-get.8.html) 与 [apt.conf](https://manpages.ubuntu.com/manpages/noble/en/man5/apt.conf.5.html)：索引目标、验证、配置读取顺序和钩子隔离。

- 本机 `modinfo(8)` 和 [EGL 接口](https://registry.khronos.org/EGL/sdk/docs/man/html/eglIntro.xhtml)：模块元数据与离屏上下文。

运行 `python3 -m unittest discover -s tests -v`。APT 集成测试只使用临时本地文件仓库，覆盖签名通过、未签名、过期、绕过信任、钩子隔离和真实依赖解析；缺少可选组件时明确跳过相应测试。其余案例使用合成数据，涵盖驱动换版、内核不匹配、可选固件、绘制结果、配置覆盖、人工反馈失效和旧档案续接。真实本机结果单独记录，不能从模拟案例推断全部硬件支持。
