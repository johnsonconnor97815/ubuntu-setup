# 只读检查原型

版本：`0.8.0`。当前实现负责采集、存档、比较变化和生成有限检查报告，提供 [独立检测规则与能力目录](detection-rules.md)，以及保存后默认打开的 [HTML 报告](html-reports.md)。报告先说明具体问题和用户、助手各自的下一步，再分别列出已发现的问题、后续维护与未查清事项。完整检查表、电脑信息和技术记录放在后面展开查看。5 项扩展检查和设备确认接口见 [扩展检查](extended-checks.md)。完整维护工作流见 [workflow.md](workflow.md)。

主程序使用 Python 标准库，运行环境为 Linux、Python 3.10 或更新版本；实测使用 Python 3.12.3。新增探测还调用已有的 python3-apt、modinfo 和图形库等系统组件；缺少组件时不自动安装。没有安装、修复、修改本机索引、切换驱动、重启或后台监听操作。程序写入自己的状态目录，可选联网索引与图形测试的临时文件用完清理。

当前由 Agent 的本地命令执行工具调用此程序；没有内置语言模型、专用 Skill 或 MCP 接入，也没有自动改进能力的机制。后续设计和实施顺序见 [Agent 接入与能力改进](agent-integration-and-evolution.md)。

## 命令

在仓库根目录执行。推荐使用启动器，它会在进入 Python 前检查运行时：

```sh
./ubuntu-setup inspect
./ubuntu-setup inspect --format json
./ubuntu-setup inspect --format json --no-open
./ubuntu-setup inspect --watch-config /etc/apt/sources.list
./ubuntu-setup inspect --help
./ubuntu-setup capabilities --format json
```

| 参数 | 行为 |
| --- | --- |
| `--state-dir PATH` | 使用仓库之外的独立私有目录；一个目录绑定一个目标和真实或模拟来源 |
| `--fixture FILE` | 使用合成观察 JSON，不读取本机系统信息；必须同时指定独立状态目录 |
| `--watch-config PATH` | 增加一个配置文件的内容摘要及基本属性监测，可重复指定；与 `--fixture` 互斥 |
| `--format text` / `--format json` | 终端输出摘要或 JSON 结果；两种方式都保存 HTML 报告与详细快照 |
| `--no-open` | 仅保存 HTML 报告，不自动打开浏览器；默认保存后请求打开 |
| `--timeout SECONDS` | 每个探测命令的超时，默认 5 秒，允许大于 0 且不超过 30 秒 |
| `--online` | 在临时目录下载和核实 APT 索引，建议配合 `--timeout 30`；不修改系统索引 |
| `--confirm-from RUN_ID`、`--confirm-device DEVICE=RESULT` | 记录用户针对最新报告实际验证的显示、声音或输入结果；复核发现环境变化时不沿用 |

启动器还提供 `./ubuntu-setup runtime status [--format json]`。它会启动候选解释器读取版本，只检查是否存在可用的 Python 3.10+，不启动检查、不安装软件。找不到时退出码为 `3`，并给出 `swkit python configure --python 3.12`。`2` 表示启动器参数错误，或 Python 程序的参数、档案或读写错误；`130` 表示用户中断。报告完成不代表系统稳定，也不代表可以自动执行变更。

默认在完整保存并发布报告后通过当前桌面的 `xdg-open` 打开 HTML；调用等待最多 5 秒，不安装浏览器、不修改默认应用。无桌面会话、缺少打开工具或启动失败时仍保留报告并返回路径，报告完成状态不受影响。能力查询不启动浏览器。

默认目录为 `${XDG_STATE_HOME}/ubuntu-setup/targets/local/`；未设置该变量时使用 `~/.local/state/ubuntu-setup/targets/local/`。`XDG_STATE_HOME` 必须是绝对路径。状态目录仅当前管理用户可访问，已有非私有目录会被拒绝，程序不会改动其权限。

## 实际采集范围

| 观察范围 | 实现方法 | 边界 |
| --- | --- | --- |
| `os` | `/etc/os-release` 与当前进程的 CPU 架构 | Ubuntu 24.04 / x86_64 为首批验证组合，其他组合保留待核实 |
| `environment` | `systemd-detect-virt --container`，按需再读 `--vm` | 区分真实主机、虚拟机、容器与 WSL；检测失败不默认当真实主机 |
| `resources` | `/proc/cpuinfo`、`/proc/meminfo`、逻辑处理器数 | 只表示可读取的容量，不能代替负载或性能验证 |
| `storage` | 根文件系统的 `statvfs` 信息 | 只判断只读标志和空间耗尽；未按具体安装计划检查空间、备份或其他挂载点 |
| `kernel`、`boot` | 当前内核版本与启动标识 | 小块读取系统文件；启动标识改变不代表驱动功能已通过 |
| `kernel.next_boot` | 显式保留未知 | 未解析引导选择，不能从“已安装最新内核”推断下次启动版本 |
| `packages.dpkg` | `dpkg-query -W` 的指定字段输出 | 包名、版本、架构、登记状态和错误标志；依赖与候选解析另存于 `checks.packages` |
| `packages.snap` | `snap list --color=never --unicode=never` | 当前列出的修订，不含所有旧修订；工具缺失或输出不认识时记未知 |
| `packages.flatpak.system`、`packages.flatpak.user` | `flatpak list` 指定 `ref`、`version`、`active` 列，含应用和运行时 | 默认系统安装与当前用户；不含自定义 installation 和其他用户 |
| `sources.apt` | 默认 `.list`、`.sources` 文件摘要 | 不保存带凭据的源内容，不证明仓库签名或可用性 |
| `metadata.apt` | 本地索引文件数及文件时间 | 不更新索引；文件时间不等于来源已核实或软件已更新 |
| `hardware.pci`、`hardware.usb` | sysfs 中的厂商、设备与类别标识 | 不读取设备序列号；按总线位置比较，同型号设备换位可能呈现为新增和未检测到 |
| `drivers.bindings` | 设备到驱动和模块的关联，包含 USB 接口 | 绑定关系不等于设备实际可用 |
| `drivers.modules` | `/proc/modules` 与模块可提供的 `version`、`srcversion` | 不含内建驱动；缺少版本字段保留 `null`，不能证明模块代码没有变化 |
| `drivers.secure_boot` | `mokutil --sb-state` | 工具或固件接口不可用时为未知，不能推断为关闭；未验证每个模块的签名 |
| `drivers.dkms` | `dkms status` 的只读清单 | 保存原始状态行；检测规则核对当前内核的安装记录，不能据此证明驱动兼容或设备功能 |
| `reboot` | `/run/reboot-required` 提示与此前等待记录 | 提示消失但未证实所等待的重启时，继续保留待验证 |
| `services` | 当前可见的失败系统服务及相关单元 | 有失败项时明确报告异常并列出名称；影响需要结合用途判断，未检查所有用户服务或服务实际功能 |
| `configs` | 用户指定文件的摘要、大小、权限和存在状态 | 不保存内容，未校验语法或实际生效；取消监测不表示文件被删除 |
| `checks.packages`、`checks.updates` | APT 依赖解析、候选变化、源信任设置、可选隔离联网核实 | 不覆盖全部软件和支持期限；不安装软件，细节见扩展检查文档 |
| `checks.drivers`、`checks.hardware` | 模块与设备匹配、运行和磁盘版本、有限绘制测试与人工使用确认 | 不证明全部驱动与硬件功能；下一次启动内核仍未核实 |
| `checks.configs` | sysctl.d 数字设置与生效值、已加载单元配置状态及文件摘要 | 不支持的格式或额外文件保持未知，不自动应用配置 |

工具缺失、权限不足、超时、读取过程中对象消失或输出无法解析时，该范围保存为未知，其他可独立采集的范围继续。不安装采集依赖，也不使用 `sudo`。

未扫描全部手动安装软件、容器内应用、用户运行环境或全部配置。采集范围都有记录；一次检查由多次读取组成，不是整台机器在同一时刻的原子快照。后续真正执行系统操作前还须重新核对前置条件。

## 检查和变化判断

原型提供系统组合、环境识别、包登记状态、根文件系统基本条件、重启提示、模块清单、DKMS 安装记录和失败服务清单等有限检查。规则的适用条件、具体通过范围和证据说明见 [检测规则](detection-rules.md)。检查名和原因限定每项“通过”的含义。

上述 5 项扩展检查已提供具体判断分支，并明确列出各自限制；不再统一作为占位项。信息缺失或未覆盖部分仍保留未知，不会因为包已安装、模块已加载或没有失败服务就报告系统全面稳定。

每次运行重新采集和评估，比较当前与前一次记录：

- 软件清单中的版本、登记状态或修订变化会被列出；消失只表示不再出现在相应安装来源。
- 硬件暂时消失标为“本次未检测到”，不自动清理驱动。
- 某范围检测失败时保存 `value: null`，仅引用上次已知观察；恢复检测后可与带原始时间的上次已知值比较。
- 采集版本或覆盖范围变化单独报告，避免把停止监测、改变采集方式误报成卸载或移除。
- 根据变化列出此前失效的检查，再生成本次结果；旧报告保留为历史证据。
- 每条规则有独立版本；规则新增、更新和移除另行报告，相关旧结论失效。采集逻辑版本未变时，不将程序升级误报为机器变化。
- 软件变化与驱动的关联使用有限的组件类别规则，只能提示复查方向。完整依赖影响仍需解析，不能用这些规则批准安装。

可用空间的一般波动不列成系统配置变化，但每次仍会复查；空间耗尽或文件系统只读变化会被报告。计划、授权、任务依赖和真实系统修复都尚未接入。

## 实际存储格式

`--state-dir` 直接指向一个目标的记录目录，目录内为：

```text
identity.json
.lock
inventory/
  current.json
  snapshots/<run-id>.json
assessments/<run-id>.json
runs/<run-id>/
  state.json
  events.jsonl
  changes.json
  report.html
```

记录格式版本为 `schema_version: 1`。快照保存各范围的状态、值、采集时间、覆盖范围、采集版本和必要的历史引用。JSON 输出包含检查、变化、失效结论、采集状态和报告位置；完整软件和设备清单从对应快照读取。`0.2.0` 增加每条规则的证据引用、规则版本清单与变化、快照和检查记录路径，原有字段保留，仍可读取 `0.1.0` 的档案。

`0.3.0` 的运行状态新增 `report_file: "report.html"`，可继续读取没有该字段的旧 Markdown 记录；历史报告保持原样。终端 JSON 新增 `report_format` 和 `browser_open`。HTML 包含可展开的采集明细，无外部资源依赖，文件权限沿用私有记录规则；旧程序不能直接续接新增 HTML 的运行记录，详见 [兼容说明](html-reports.md)。

`0.4.0` 的检查结果增加可选 `reason_code`，调用结果增加 `report_content_version`。原有 JSON 状态和字段含义保留，旧记录不要求存在原因编号。面向用户的显示状态更细，区分读取信息、有限检查通过、程序未实现和检查失败等情况；不会据此修改已保存的检查结论。采集版本仍为 `0.1.0`，本次判断逻辑和规则版本均未变化。

`0.5.0` 调整 HTML 模板与文案版本（`2`），优先显示用户需要关注与处理的内容。统计、完整检查目录和机器信息默认折叠，摘要中的链接可直接展开对应依据。原有 JSON 格式、采集范围、规则判断与版本均保留。识别已核对的 NVIDIA 后台任务名称只用于说明对象，不作为显卡或驱动故障的证据。

`0.6.0` 将页面调整为连续的报告正文，文案版本为 `3`。标题、检查时间、结论与处理建议、完整结果表、范围与电脑信息、前后变化均直接显示，技术依据和原始记录移至附录。结果表与附录使用同一份检查记录；结论按检查项计数，不将失败对象数量当成故障原因数量。JSON 格式、采集范围及规则判断与版本均未变化。

`0.7.0` 将 5 条占位规则实现为版本 `2`，文案版本升为 `4`，新增 5 个 `checks.*` 观察范围。原范围的采集版本保持 `0.1.0`，新增范围为 `0.2.0`。旧快照、检查和报告不改写；旧完整范围仍可续接。新增参数为 `--online`、`--confirm-from`、`--confirm-device`，具体行为和限制见 [扩展检查](extended-checks.md)。

`0.8.0` 重构报告，文案版本为 `5`。开头用具体发现作为结论，把用户待办提前；问题、后续维护和未查清事项分开显示。设备使用确认只列出尚未确认的设备，自动测试的缺口仍保留。完整检查表、机器信息与证据默认折叠。记录格式、采集范围、判断规则及其版本均未变化。

一个目录使用随机生成的本地机器编号。真实目标通过 `/etc/machine-id` 的加密摘要核对，摘要使用本目录专用的随机密钥，不保存原始 machine-id；这个核对用于关联记录，不是身份认证。不同目标或真实与模拟来源冲突时拒绝混用。复制同一系统镜像且保留相同 machine-id 的机器不能仅凭该标识可靠区分，不能将目录当作跨机器授权凭据。

写入使用进程锁，文件先完整写入并持久保存，再替换。快照、检查结果和报告保存后，才发布 `current.json`；程序仅承诺该私有目录内的单写入者，不阻止用户或系统的其他修改。

只读任务使用 `collecting`、`completed`、`interrupted` 状态，尚未实现设计草案中的系统操作状态。检查中断后保留资料，下次重新采集；已完成报告但尚未发布索引时，核对完整资料和前序关系后恢复索引。损坏、未知格式或冲突记录报错，不当成空档案重新开始。残缺的历史事件原样保留，不根据其中半条事件推断完成。

新建的状态文件使用 `0600`，指定的状态目录及其内部管理目录使用 `0700`。真实档案、报告和日志不写入仓库；原型尚未创建配置备份，也不执行恢复操作。
